# A1 overlay: measurement tools (plan milestone M3)

Owner: builder-a1. Files: `overlays/A1/` (copied onto the workspace root), `arms/A1.toml`, this doc,
and the verification helpers in `docs/A1/`.

## What ships in `overlays/A1/`
| file | what |
|---|---|
| `phase_table.cuh` | `PT_INIT/PT_FINISH`, barrier stamps `PT_ARRIVE/PT_RELEASE(id)`, `PHASE_BEGIN/END(id)`, `PT_MARK(id)`, `PT_SPIN(stmt)`, host `phase_table_bind()` + `PHASE_TABLE_PYBIND(m)`. Compiles to nothing without `-DPHASE_TABLE`. One writer per block (thread 0) records `%globaltimer` into a self-describing uint64 buffer (magic, grid size, per-block regions of 4-word records). |
| `phase_table` → `.a1/phase_table.py` | Uses the benchmark's `build_timeline(case) -> (run, names)` contract (same as `./timeline_candidate`), spawns all ranks under `./gpu_run -g <case gpus>`, warms up 2 launches, captures N, and prints per phase (= interval closed by a barrier site): wall, share of span, slowest/mean block busy, skew, last-arrival→release, mean barrier wait, cross-rank skew (`rskew`), cross-rank wall spread (`xsprd`), slowest rank. It also prints the critical-path split per rank (work + intra-GPU skew + sync + tail), wall by context (`PT_MARK`), sub-phases, and `--group NAME=REGEX` shares. It writes `reports/phase_table-*/summary.json`, `table.txt` and the raw buffers. `--analyze DIR` re-analyses without a GPU; `--self-test` runs synthetic buffers. |
| `profile_candidate_all_ranks` → `.a1/ncu_all_ranks.py`, `.a1/ncu_rank.py` | Starts one ncu per rank with `--replay-mode application --target-processes all --profile-from-start off`. Each replay pass re-runs every rank, which joins a fresh per-pass file rendezvous, and the warmed launch in the cudaProfilerStart/Stop window is profiled. All of it runs under `./gpu_run -g N -- timeout -k 30 T`. Metric sets with measured pass counts: `default` (1 pass: DRAM r/w bytes, duration, inst, tensor/tc pipe), `l2` (3), `pipes` (~3), `stalls` (2, PC sampling). It writes `reports/ncu_all_ranks-*/{table.txt,summary.json,prof_r<rank>.ncu-rep,rank*.log}`. |
| `flag_audit` → `.a1/flag_audit.py` | Finds the sources the Python build compiles (file names in the nvcc/cpp_extension build code, plus local includes). It reads the shipped `-D/-U` flags from the nvcc command lists via the AST; for `os.environ.get(X, default)` in the command it uses the default, because the grader does not set env vars. A small preprocessor evaluates every `#if/#ifdef/#ifndef/#elif/#else` with in-source `#define`s and classifies each one as default-value, include-guard, platform, variant or optional block. It matches active optional blocks (and active `#ifdef` opt-ins) against NOTES.md clauses that contain negative words (no gain/slower/reverted/off/neutral/…), by macro name or by rare shared terms (block body, plus comments/heads of the functions it calls). Exit 1 on findings. `--flags`, `--env`, `--all`, `--self-test`. |
| `TASK.d/A1.md` | Agent instructions: when to use each tool, one-line commands, how to instrument, how to read the output. Nothing DSv4.1-specific. |

## Known limits
- **phase_table:**
  - Barrier sequences must match across blocks; they are keyed by (site id, occurrence).
  - Cross-rank columns need identical sequences on all ranks; otherwise the tool says so and omits them.
  - Stamp overhead in the seed: span 21.86 ms (NO_PF) against 21.13 ms uninstrumented in-device
    (+3.5%; MKPROF was +1.9%). The table shows *where* time goes, and `check_candidate`
    confirms speedups.
  - In barrier implementations where one block waits for the peers (XBAR-style), that wait counts
    as the block's busy time and so shows up as skew. Use `rskew`/`xsprd` for cross-rank effects.
  - `globaltimer` resolution is 32 ns; only durations are compared across GPUs.
- **profile_candidate_all_ranks:**
  - A single ncu over all ranks deadlocks: ncu serializes profiled kernels across the processes it
    controls. That was observed and is why the tool runs one ncu per rank.
  - Each pass costs about 1–1.5 min of all 8 GPUs, so `sm__throughput` (9 passes) is left out of
    every set.
  - Duration, % metrics and total instruction counts include the spin on peer flags caused by
    start skew under ncu. Bytes and tensor-pipe counts are valid.
- **flag_audit:**
  - Shipped flags come from static analysis of the build code; flags built at runtime in other
    ways need `--flags`.
  - NOTES matching is lexical. It can produce false positives on rare shared words (e.g.
    "staging" also matched a clause about a split-K experiment) and false negatives when NOTES
    uses words absent from the code.
  - `__CUDA_ARCH__`-style platform conditionals are listed but not evaluated per compilation pass.
- **Not verified:** the tools inside an isolated run user's workspace with the harness's real
  `./gpu_run` (I used `docs/A1/gpu_run_stub`, which calls `gpu_lease` the same way).

## GPU use
151 GPU-minutes in total for builder-a1 in `/srv/ss/lease.jsonl` (about 19 min of the whole node). Most of it was
the first all-ranks ncu attempts: one ncu over all ranks deadlocked, and a 15-metric set needed 11 replay passes
before I killed it. Each final verification run is short: both phase_table captures took 67 s in one 8-GPU lease,
and the 1-pass ncu run takes a few minutes. The ncu pass counts were sized on 1 GPU (`docs/A1/passcount*.sh`).

# A2: hardware knowledge pack (B300 primitive costs + two skills)

- **B300 rows in `./primdb`.** `progress/microbench/primdb_local.jsonl` starts with ~3,100 rows measured on
  this node's GPUs (B300, sm_103a) by the benchmark's primbench suite. They carry the conditions `gpu=B300` and
  `arch=sm_103a`; the seed rows (no `gpu` field) are B200. Query only B300 rows by adding `gpu=B300`, e.g.
  `./primdb q tc_mma gpu=B300 kind=f8f6f4`, `./primdb q dequant gpu=B300`, `./primdb q mem gpu=B300`, `./primdb q sync gpu=B300`,
  `./primdb compare gemm M=8 N=4096 K=7168 gpu=B300`. Your own `./primdb add` rows go into the same file.
  To measure more B300 points: `primbench_b300/run_seed.sh` (build, then `GPU="./gpu_run -g 1 --"` run).
- **Skill `blackwell-block-scaled-gemm`** (`.claude/skills/`): native FP4/FP8 tensor-core GEMM for
  M <= 64 rows (`tcgen05.mma kind::mxf8f6f4.block_scale`, TMA of packed FP4, scales in TMEM, swap-AB,
  smem ring, split-K, PDL), with a tested standalone example and measured B300 numbers.
- **Skill `multi-gpu-sync`**: counters vs grid barriers, deadlines, NVLink push/mailbox/multicast
  all-reduce, chunked overlap, balancing work across GPUs/blocks (incl. slicing an FFN's intermediate dim),
  cooperative-kernel deadlock hazards; tested single-GPU example.
- B300 facts: `tcgen05.mma kind::i8` does not exist on sm_103a; FP8 `mma.sync` is emulated (see rows).

**Big-ticket first.** Before you spend time on an idea, write down how many ms of the current latency
it can remove at most (bytes / achievable bandwidth, barrier count x cost, imbalance = slowest - mean),
from a profile or from `./primdb` rows. Rank the ideas by that number and start with the largest; drop
an idea whose ceiling is below the run-to-run noise. Re-rank after each landed change.
